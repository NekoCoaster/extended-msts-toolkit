# Stored motion versus observed position/orientation changes

`analyse_motion_differences.py` reuses three immutable vehicle-motion captures and records their SHA256s in `motion-difference-summary.json`. It compares adjacent successful observations only, with0<simulation delta<=1second, both unpaused, neither car derailed, successful body-pointer checks at both ends, and unchanged train address/car identity/definition/links. Body buffer addresses may legitimately swap. It resets continuity across error rows. No outlier clipping or origin correction is applied. These are observational consistency checks, not a reference physics implementation.

For each eligible car pair it compares `(position1-position0)/dt` with mean body88 velocity, and `(forward1-forward0)/dt` with `mean(body94 angular velocity) cross mean(forward)`. Results report vector-norm discrepancies, separate same-clock subsets, and the worst examples. Same-clock means each endpoint read saw an unchanged simulation clock; it does not establish an atomic read, common producer phase or constant coordinate origin. Threshold1e-6/s is used only to count appreciable forward-vector changes; both endpoint angular velocities must be exactly zero for that count.
